# 疑問に思ったときは

[한국어](../EXPLANATIONS.md) | [English](../en/EXPLANATIONS.md) | 日本語

アプリを使っていて「どうしてこうなるのだろう？」と思ったときに読むガイドです。どこに何があるかは[ユーザーマニュアル](MANUAL.md)、目的の操作方法は
[操作ガイド](HOW-TO.md)、困ったときは[トラブルシューティング](TROUBLESHOOTING.md)をご覧ください。

<a id="11-기울기-한도가-18-dboct-가-아닌-까닭"></a>
## 過剰設定の警告はなぜ表示されるのですか？

DSP ページの過剰設定検出機能が、現在の設定で音が大きくなりすぎたり、カーブが急峻に立ち上がりすぎたりしている箇所を検出すると警告を表示します。
警告が表示されるだけでは、音は変わりません。

AutoEq が出力するカーブでもこの上限をわずかに超えることがあります。そのため、AutoEq の数値をそのまま上限にはせず、1 つのフィルターでは
作れない狭いブーストや、合成カーブとブーストのみのカーブの両方が急峻な箇所でのみ警告します。
警告が出たら、**補正を提案…** から修正方法を選べます。

<a id="12-부스트-한도가-62-db-이고-10-khz-위는-평균인-까닭"></a>
## ブーストの警告はどこから表示されますか？

調整後の EQ カーブが +6.2 dB を超える箇所で表示されます。+6 dB に AutoEq がカーブ生成時に設ける余裕（0.2 dB）を加えた値です。
10 kHz より高い帯域は、1 点ではなく帯域の平均で判定します。その上の帯域はフィルターが正確に追従しにくい領域であるためです。

クリッピング（音割れ）を防ぐのはこの警告ではなく、PCMヘッドルームです。

## EQ の補正はどのように行われますか？

自動で行われるのは **クリッピング防止：プリアンプを自動で下げる** の 1 つだけで、初期設定ではオフになっています。オンにすると、EQ · Ostrum · クロスフィードを合算した音が 0 dB を
超えたときに Preamp だけが必要な分だけ下がります。バンドには触れず、カーブの形もそのままです。

バンドを修正する補正は、**補正を提案…** で **補正を適用** を押したときだけ行われます。ウィンドウは **業界の慣例** で開きます。Preamp だけを下げて
カーブの形はそのままにします。横の **改善** を選ぶと、上限を超えたブーストや急峻な斜面を作っているバンドだけを最小限に修正します。
改善はカーブの形を変えるため、ウィンドウに警告が表示され、適用するかどうかは自分で決めます。適用した後も **補正を取り消す** で 1 回前に戻せます。

## Preamp はなぜ下がるのですか？

EQ で特定の帯域を上げると全体の音が大きくなり、音割れすることがあります。Preamp はその分だけ全体をあらかじめ下げておく値です。
AutoEq などの EQ ファイルにはこの値も含まれています。そのため、EQ をオンにすると音が少し小さくなることがあります。

形を比較しやすいように、DSP グラフは Preamp を除いたカーブで描画されます。実際の音には Preamp がそのままかかっています。

<a id="2-이득-조절이-셋인-까닭--pcm-헤드룸--eq-preamp--ostrum-headroom"></a>
## 音量を下げる設定がなぜ 3 つあるのですか？

3 つとも全体の大きさを下げますが、配置されている場所が異なるため防ぐものが違います。

- **PCMヘッドルーム**: すべての処理の最後段で**クリッピング**を防ぎます。初期設定は自動です。
- **EQ Preamp**: EQ の最前段で EQ のレベルを決めます。「Preamp はなぜ下がるのですか？」で説明した Preamp です。
- **Ostrum Headroom**: Ostrum 内で Harmonics がかかりすぎないようにします。推奨値が表示されたら自分で動かします。横の **変わるたびに自動で**（初期設定オフ）をオンにしたときだけ、ノブが推奨値に追従します。

1 つにまとめると、片方のために下げたときに他方の音まで変わってしまうため、分けてあります。自動 PCMヘッドルームは、前の 2 つですでに下げた分を
差し引いた残りのブースト分だけを下げるため、同じ量を二重に下げることはありません。通常は 3 つとも触る必要はありません。

## PCM Direct とエンジン出力は何が違いますか？

**PCM Direct** では、Fidenne は音を処理しません。再生アプリの音が macOS を経由して DAC に送られ、DAC のサンプルレートは
曲ごとには合わせず、再生開始時に 1 回だけ決まります（Spotify は 44.1 kHz）。曲と異なる場合は macOS が変換します。EQ · Ostrum · クロスフィードは通りません。

**エンジン出力**（DSD または PCM オーバーサンプリング）は、Fidenne エンジンが音を処理して DAC に送ります。EQ などをすべてオフにしても、その形式に必要な変換
（アップサンプリング · 変調 · ディザ · ヘッドルーム）はかかるため、選んだフィルターと変調器によって音の傾向が変わることがあります。

## どのデバイスでエンジン出力を使えますか？

エンジンの PCM 出力は 44.1 · 48 kHz 系列のレート（44.1 ~ 768 kHz）から選び、新しい設定の初期値は音源レート維持です。USB で直接接続した DAC は
このうち 1 つでも受け取れる 2 チャンネルデバイスであれば使えます（DSD はその DAC が DoP に対応している場合のみ）。352.8 kHz に対応していなくても
対応しているレートに下げて使えます。44.1 ~ 768 kHz の対応レートを 1 つも受け取れないか、2 チャンネルではないデバイス（一部のドングル · 4 · 8 チャンネルインターフェース）は出力デバイス
一覧で名前の末尾に表示され、PCM Direct でのみ聴けます。

Fidenne は内蔵スピーカー · 3.5 mm 端子 · AirPods（Bluetooth）· HDMI にも EQ · Ostrum · クロスフィード · フィルターを適用した音を処理して送ります。最後に macOS がシステムミキサーでミックスしてデバイスに送るため、ビットパーフェクトではありません（**システムミキサー経由・ビットパーフェクトではありません**）。
エンジンはデバイスの現在のレート以下の対応 PCM レート（44.1 ~ 768 kHz）のうち最も高いレートで処理し、必要に応じて macOS がデバイスレートに変換します。デバイスのレートと音量は macOS が決め、音量調整も Mac 側のものになります。原音データをそのまま送るには、外付け DAC の整数 PCM または DSD を使います。

DAC をまだ選んでいないか確認されていない場合は、PCM Direct で開始します。DAC が DSD に対応していれば DSD でも送れます。

## 出力レートはどのように決まりますか？

**出力レート** はエンジンが DAC に送り出すレートで、フィルター · EQ もそのレートで処理されます。自分で 1 つ選ぶと、どの曲でもそのレートで出力されます。
**音源のレート系列に合わせる** をオンにすると、曲の系列に従います — 44.1 kHz 系列（44.1 · 88.2 · 176.4 …）の曲は 44.1 系列で、48 kHz 系列（48 · 96 · 192 …）の曲は
48 系列で出力されるため、整数倍ではない変換（例: 44.1 → 48）を避けられます。このとき選ぶのは倍率で、**自動（デバイスの最高）** は DAC が受け取れる最も高い倍率です。
曲のレートがまだ分からないか推定にすぎない場合は系列を変えず、系列が変わる曲間では DAC が新しいレートを捕捉するまで一瞬無音になります。
レートが高いほど良く聴こえるかは確認できていません。低いレートでは 24-bit のノイズ余裕が基準に届かないことがあり、その場合はその旨を画面に表示します。

## 曲の間に無音があるのはなぜですか？

レートが変わる曲の間では、DAC が新しいレートに合わせる時間が必要であり、次の曲の最初の音が途切れないように前にデジタル無音を置きます。
**そのまま** は音に触れず曲末をそのまま残し、レートが変わるときだけ前に短い無音を置きます。**なめらかに** は曲が終わる直前の 0.02 秒を絞ります。
DAC ごとに設定された待機時間（**レート変更時の待機**）が短くて最初の音が途切れる場合は長くします。この方式はローカルファイルの PCM 出力に適用されます。

## 高域にフィルターを置いた EQ の音が変わることがあるのはなぜですか？

デジタル EQ フィルターはアナログフィルターをデジタルに移したものですが、移し方によっては出力レートの半分（ナイキスト周波数）付近でカーブが曲がり、設定したものと
異なる形になります。現在のバージョンでは係数をアナログの原型に合わせて計算しているため、高い周波数（特に 16 kHz 以上）で設定したカーブが実際のカーブにより近くなります。高域にフィルターを置いた
EQ は、同じ設定でも高域の音が少し変わることがあります。352.8 kHz と DSD では差はごく小さく、44.1 · 48 kHz のような低いレートでは顕著です。

## 曲が自動で次に進むとき、DAC のレートがそのままなのはなぜですか？

DAC のサンプルレートを変えるには、音を一度止めて開き直す必要があります。曲が連続して再生されている途中でそれを行うと、音が途切れたりノイズが入ったりするおそれがあるため、
Fidenne は **再生中の音には触れません。** 曲が自動で次の曲に進むときにレートが異なる場合は、現在のレートをそのまま維持し、macOS が変換します。

レートを曲に合わせる処理は、ユーザーが曲を直接選んで再生を始めるとき、音が出る前にのみ行います。曲ごとに判明したレートはサービスと根拠（曲 · アルバム）を
区別して記憶しておき、そのときに使います。同じアルバムでも発売版が異なれば同じ記憶とはみなしません。

## Trellis で再生が止まることがあるのはなぜですか？

Trellis はこれから来る音まで先読みしながらビットを選ぶ変換方式のため、計算負荷が高いです。音は決まった時刻ごとに DAC に届く必要がありますが、
この Mac がその時刻までに計算を終えられない場合、途切れた音を流す代わりに再生を止めて理由を知らせます。このとき「精密」·「安全」や CLANS に変えると
計算が軽くなります。Fidenne が方式を勝手に変えることはなく、どれを選ぶかはユーザー次第です。

## Cardinal Sinc 128K · 64K は他のフィルターと何が違いますか？

長タップ拡張の固定長 sinc フィルターで、128K はタップ数が約 13 万個（遅延約 116 ms）、64K は約 6 万 5 千個（遅延約 70 ms）です。どちらもカットオフは 22.05 · 24 kHz に
固定されており、名前の末尾に **（ソースに追従）** が付くペアはカットオフが曲のレートに追従します。44.1 · 48 kHz の曲ではペアと同じ係数になるため音も同じで、他のレートの曲でのみ異なります。
長いほど音が出るまでにかかる時間が増えるため、映像とずれることがあります。

## 歌詞の翻訳はどこで行われますか？

翻訳をオンにしておくと、Fidenne は上から順に試し、前の段階がうまくいかない場合は次に移ります — ① 自分の API キーで選んだ AI プロバイダー（オンにしているときのみ）→
② この Mac 内の Apple モデル（Apple Intelligence、キー不要、歌詞は Mac の外に出ません）→ ③ macOS 翻訳 → ④ 原文。
① のみが歌詞の原文の行と曲名 · アーティスト名を選んだプロバイダーに直接送信し、料金はご自身のアカウントに課金されます。②〜④ は Mac の外に送信しません。
Fidenne は 1 つのプロバイダーが失敗したからといって別のプロバイダーにこっそり切り替えたりはしません。何が送信されるかは[プライバシーポリシー](../../../PRIVACY.ja.md)に記載されています。
翻訳はこの Mac で閲覧する個人的な鑑賞用であり、歌詞や翻訳を他の場所に公開する場合の責任はユーザーにあります。歌詞の著作権は各権利者に帰属します。

## Fidenne Inlet を別途インストールするのはなぜですか？

Fidenne Inlet は、音楽アプリが「スピーカー」のように音を送れる仮想オーディオデバイスです。macOS ではこの種のデバイスをアプリではなく
システムオーディオサービスが読み込むため、アプリ内に置くことができず、システムフォルダ（`/Library/Audio/Plug-Ins/HAL`）に配置する必要があります。
そのため、インストール時に管理者パスワードを 1 回求められ、オーディオサービスを再起動する間に一瞬すべての音が途切れます。他の仮想オーディオデバイスも同じ方法でインストールします。

インストールするのは Inlet の 1 つだけで、インストール直前に Fidenne の署名が正しいか再度確認します。削除するには、**入出力 · 診断 › 入力デバイスと出力デバイス** で **削除…** を押します。

インストールしたくない場合は、初期設定で **システムタップ** を選びます。インストール不要で使えますが、macOS が音を 48 kHz に変換して渡します。
Inlet は再生アプリの元のサンプルレートをそのまま受け取れるため推奨しています。

## アップデートはどこに接続しますか？

アップデートの確認では、github.com の新バージョン案内ファイルを読み込みます。GitHub はこのファイルや新バージョンを `release-assets.githubusercontent.com` に
リダイレクトすることがあります。アプリが行う他の接続は、サーバーが別のアドレスに案内しても許可された接続先である場合のみ従います。アップデートについてはアプリが最初のアドレスだけを確認し、
その後の案内はアップデートツール（Sparkle）が直接たどるため、ここだけはアプリがリダイレクト先を再確認できません。取得した新バージョンは署名が正しい場合のみインストールされ、インストールはアップデート画面で自分で選んだときだけ行われます。
何が送信されるかは[プライバシーポリシー](../../../PRIVACY.ja.md)に記載されています。

## Safari 機能拡張はなぜアプリケーションフォルダから開く必要があるのですか？

Safari 機能拡張は Fidenne アプリの内部に含まれているため、Safari はアプリがアプリケーションフォルダなどの正規の場所にあるときにその機能拡張を見つけます。ダウンロードした .dmg の中から直接開いたり、
ダウンロードフォルダから開いたりしたアプリは、macOS が隔離された一時コピーとして実行するため、Safari が機能拡張を表示できません。
Fidenne はこの状態を検知して `Safari機能拡張は、Fidenneをアプリケーションフォルダに移動して開き直すと、Safariに表示されます。` と通知します。

## マルチチャンネルファイルはなぜ処理されずそのまま出力されるのですか？

Fidenne の EQ · Ostrum · クロスフィード · フィルターは 2 チャンネル向けです。5.1 · 7.1 · 7.1.4 ファイルは、マルチチャンネル出力デバイスのスピーカーにチャンネル名のとおりにつないでサンプルをそのまま送り、ダウンミックスや処理は行いません。
デバイスがそのチャンネル数に対応していない場合は、勝手に 2 チャンネルに減らさず理由を伝えて停止します。ヘッドホンで聴きたい場合は、**DSP › プラグイン** の **マルチチャンネル入力プラグイン** で空間オーディオ Audio Unit を自分で選ぶと、そのプラグインが返した 2 チャンネルが EQ と出力につながります。処理は選んだプラグインのものが適用されます。

## 映像が音なしで再生されるのはなぜですか？

アルバムモードの映像ページは音楽を聴く画面のため、映像の音をオフにして音楽の再生位置に合わせて映像を動かします。ページが映像の位置を読み取れるときだけ同期し、合わせる映像がない場合はその旨を知らせます。
Web ページ上で映像が自動的に音をオンにしようとした場合、人が操作したときでなければ再びオフにします。曲に使った映像はこの Mac にのみ記憶されます。


## 狭い画面ではなぜ「映像の上に字幕」のほうが映像を大きく表示できるのですか？

映像のみ表示では、**歌詞欄**が映像の横に幅を取るため、映像は元のアスペクト比を保ったまま残りのスペースに収まります。ノートパソコンのようにウィンドウが狭いと残りのスペースが小さくなり、映像も小さくなります。**映像の上に字幕** は映像の上に歌詞を重ねるため、映像がウィンドウ全体を使えます。どちらが良いかは画面の幅や好みに応じて、**大きい表示の歌詞** から自分で選べます。

## YouTube Music の曲をクリックするとなぜそのブラウザに移動するのですか？

2 つ以上のブラウザが接続されているとき、Fidenne は「最後に前面に表示した YouTube Music タブ」を人が最も最近使った場所とみなします。タブが自動的に表示されたり音だけを出したりしても前面に表示したとは数えず、人がそのタブをクリックして前面に出したときだけ数えます。前面に出しただけでは再生や停止は一切行われず、次に曲を選ぶクリックだけがそのタブを使います。
