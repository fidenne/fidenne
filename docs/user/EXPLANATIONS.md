# 궁금할 때

앱을 쓰다가 "왜 이렇게 되지?" 싶을 때 읽는 글입니다. 무엇이 어디에 있는지는 [사용 설명서](MANUAL.md), 무엇을 하려면 어떻게 하는지는
[할 일별 지시서](HOW-TO.md), 막혔을 때는 [문제 확인 가이드](TROUBLESHOOTING.md)를 보세요.

<a id="11-기울기-한도가-18-dboct-가-아닌-까닭"></a>
## 과한 설정 경고는 왜 뜨나요?

DSP 페이지의 과한 설정 탐지기가 지금 설정으로 소리가 너무 커지거나 곡선이 너무 가파르게 솟는 곳을 찾으면 경고합니다.
경고만으로는 소리가 바뀌지 않습니다.

AutoEq 가 내놓는 곡선도 이 한도를 조금 넘을 때가 있습니다. 그래서 한도를 AutoEq 숫자 그대로 쓰지 않고, 필터 한 개로는
만들 수 없는 좁은 부스트나, 합친 곡선과 부스트만의 곡선이 모두 가파른 곳에서만 경고합니다.
경고가 뜨면 **보정 제안…** 에서 고칠 방법을 고를 수 있습니다.

<a id="12-부스트-한도가-62-db-이고-10-khz-위는-평균인-까닭"></a>
## 부스트 경고는 어디서부터 뜨나요?

맞춘 EQ 곡선이 +6.2 dB 를 넘는 곳에서 뜹니다. +6 dB 에 AutoEq 가 곡선을 만들 때 두는 여유(0.2 dB)를 더한 값입니다.
10 kHz 보다 높은 곳은 점 하나가 아니라 대역의 평균으로 따집니다. 그 위쪽은 필터가 정확히 따라가기 어려운 자리이기 때문입니다.

클리핑(소리가 잘리는 것)은 이 경고가 아니라 PCM 헤드룸이 막습니다.

## EQ 보정은 어떻게 이루어지나요?

자동으로 하는 것은 **클리핑 막기 — Preamp 자동 낮춤** 하나이고, 기본은 꺼져 있습니다. 켜면 EQ · Ostrum · 크로스피드를 더한 소리가 0 dB 를
넘을 때 Preamp 만 필요한 만큼 낮춥니다. 밴드는 건드리지 않고 곡선 모양도 그대로입니다.

밴드를 고치는 보정은 **보정 제안…** 에서 **보정 적용** 을 누를 때만 일어납니다. 창은 **업계 관례**로 열립니다. Preamp 만 내리고
곡선 모양은 그대로 둡니다. 옆의 **개선**을 고르면 넘친 부스트나 가파른 옆면을 만드는 밴드만 가장 조금 고칩니다.
개선은 곡선의 모양을 바꾸므로 창에 경고가 붙고, 적용할지는 직접 정합니다. 적용한 뒤에도 **보정 되돌리기** 로 한 번 돌아갈 수 있습니다.

## Preamp 는 왜 내려가나요?

EQ 로 어떤 대역을 올리면 전체 소리가 커져 잘릴 수 있습니다. Preamp 는 그만큼 전체를 미리 낮춰 두는 값입니다.
AutoEq 같은 EQ 파일은 이 값을 함께 가져옵니다. 그래서 EQ 를 켜면 소리가 조금 작아질 수 있습니다.

모양을 비교하기 좋도록 DSP 그래프는 Preamp 를 뺀 곡선으로 그립니다. 소리에는 Preamp 가 그대로 걸려 있습니다.

<a id="2-이득-조절이-셋인-까닭--pcm-헤드룸--eq-preamp--ostrum-headroom"></a>
## 음량을 낮추는 설정이 왜 셋인가요?

셋 다 전체 크기를 내리지만 놓인 자리가 달라 막는 것이 다릅니다.

- **PCM 헤드룸**: 모든 처리의 맨 뒤에서 **클리핑**을 막습니다. 기본은 자동입니다.
- **EQ Preamp**: EQ 의 맨 앞에서 EQ 의 레벨을 정합니다. "Preamp 는 왜 내려가나요?" 의 그 Preamp 입니다.
- **Ostrum Headroom**: Ostrum 안에서 Harmonics 가 지나치게 걸리지 않게 합니다. 권장 값이 뜨면 직접 옮깁니다. 옆의 **바뀔 때마다 자동으로**(기본 꺼짐)를 켰을 때만 노브가 권장 값을 따라갑니다.

하나로 합치면 한쪽을 위해 내릴 때 다른 쪽 소리가 달라지기 때문에 나누어 두었습니다. 자동 PCM 헤드룸은 앞의 둘이 이미 내린 만큼을
빼고 남은 부스트만 내리므로 같은 양을 두 번 내리지 않습니다. 보통은 셋 다 손대지 않아도 됩니다.

## PCM Direct 와 엔진 출력은 무엇이 다른가요?

**PCM Direct** 는 Fidenne 이 소리를 처리하지 않습니다. 재생 앱의 소리가 macOS 를 거쳐 DAC 로 나가고, DAC 의 샘플레이트는
곡마다 맞추지 않고 시작할 때 한 번 정합니다(Spotify 는 44.1 kHz). 곡과 다르면 macOS 가 바꿉니다. EQ · Ostrum · 크로스피드는 거치지 않습니다.

**엔진 출력**(DSD 또는 PCM 오버샘플)은 Fidenne 엔진이 소리를 처리해서 DAC 로 보냅니다. EQ 등을 모두 꺼도 그 형식에 필요한 변환
(업샘플링 · 변조 · 디더 · 헤드룸)은 걸리므로, 고른 필터와 변조기에 따라 소리의 성격이 달라질 수 있습니다.

## 어떤 장치에서 엔진 출력을 쓸 수 있나요?

엔진의 PCM 출력은 44.1 · 48 kHz 계열 레이트(44.1 ~ 768 kHz)에서 고르고 새 설정의 기본은 음원 레이트 유지입니다. USB 로 직접 연결한 DAC 는
이 가운데 하나라도 받는 2 채널 장치면 쓸 수 있습니다(DSD 는 그 DAC 가 DoP 를 풀 때만). 352.8 kHz 를 받지 않아도
받는 레이트로 낮춰서 쓸 수 있습니다. 44.1 ~ 768 kHz 지원 레이트를 하나도 받지 않거나 2 채널이 아닌 장치(일부 동글 · 4 · 8 채널 인터페이스)는 출력 장치
목록에 이름 끝에 표시되고 PCM Direct 로만 듣습니다.

Fidenne 이 내장 스피커 · 3.5 mm 단자 · AirPods(블루투스) · HDMI 로도 EQ · Ostrum · 크로스피드 · 필터를 적용한 소리를 처리해서 보냅니다. 마지막에 macOS 가 시스템 믹서로 섞어 장치에 보내므로 데이터가 비트 단위로 같지는 않습니다(**macOS가 다시 처리**).
엔진은 장치의 지금 레이트와 같거나 낮은 지원 PCM 레이트(44.1 ~ 768 kHz) 중 가장 높은 레이트로 처리하고, 필요하면 macOS 가 장치 레이트로 변환합니다. 장치의 레이트와 음량은 macOS 가 정하며, 음량도 Mac 의 것입니다. 원음 데이터를 그대로 보내려면 외장 DAC 의 정수 PCM 이나 DSD 를 씁니다.

DAC 를 아직 고르지 않았거나 확인되지 않았으면 PCM Direct 로 시작합니다. DAC 가 DSD 를 받으면 DSD 로도 보낼 수 있습니다.

## 출력 레이트는 어떻게 정하나요?

**출력 레이트** 는 엔진이 DAC 로 내보내는 레이트이고, 필터 · EQ 도 그 레이트로 처리합니다. 직접 하나를 고르면 어떤 곡이든 그 레이트로 나갑니다.
**음원 계열 따라가기** 를 켜면 곡의 계열을 따릅니다 — 44.1 kHz 계열(44.1 · 88.2 · 176.4 …) 곡은 44.1 계열로, 48 kHz 계열(48 · 96 · 192 …) 곡은
48 계열로 나가서, 정수배가 아닌 변환(예: 44.1 → 48)을 피합니다. 이때 고르는 것은 배수이고 **자동(장치 최고)** 은 DAC 가 받는 가장 높은 배수입니다.
곡의 레이트를 아직 모르거나 추정일 뿐이면 계열을 바꾸지 않고, 계열이 바뀌는 곡 사이에는 DAC 가 새 레이트를 잡는 동안 잠깐 조용해집니다.
레이트가 높을수록 좋게 들리는지는 확인한 것이 없습니다. 낮은 레이트에서는 24-bit 잡음 여유가 기준에 못 미칠 수 있어, 그럴 때 그 사실을 화면에 적습니다.

## 곡 사이는 왜 무음이 있나요?

레이트가 바뀌는 곡 사이에는 DAC 가 새 레이트에 맞추는 시간이 필요하고, 새 곡의 첫 소리가 잘리지 않게 앞에 디지털 무음을 둡니다.
**그대로** 는 소리를 건드리지 않고 곡 끝을 그대로 두며 레이트가 바뀔 때만 앞에 짧은 무음을 둡니다. **부드럽게** 는 곡이 끝나기 직전 0.02 초를 줄입니다.
DAC 마다 맞춰 정한 대기 시간(**레이트를 바꿀 때 기다림**)이 짧아 첫 소리가 잘리면 늘립니다. 이 방식은 로컬 파일의 PCM 출력에 적용됩니다.

## 고역에 필터를 둔 EQ 소리는 왜 달라질 수 있나요?

디지털 EQ 필터는 아날로그 필터를 디지털로 옮긴 것인데, 옮기는 방식에 따라 출력 레이트의 절반(나이퀴스트) 가까이에서 곡선이 휘어 설정한 것과
다르게 됩니다. 지금 판은 계수를 아날로그 원형에 맞춰 계산해서, 높은 주파수(특히 16 kHz 위)에서 설정한 곡선이 실제 곡선에 더 가깝습니다. 고역에 필터를 둔
EQ 는 같은 설정이어도 고역 소리가 조금 달라질 수 있습니다. 352.8 kHz 와 DSD 에서는 차이가 아주 작고, 44.1 · 48 kHz 같은 낮은 레이트에서 뚜렷합니다.

## 곡이 저절로 넘어갈 때 DAC 레이트는 왜 그대로인가요?

DAC 의 샘플레이트를 바꾸려면 소리를 잠깐 멈추고 다시 열어야 합니다. 곡이 이어지는 도중에 그렇게 하면 소리가 끊기거나 튈 수 있어서,
Fidenne 은 **들리고 있는 소리는 건드리지 않습니다.** 곡이 저절로 다음 곡으로 넘어갈 때 레이트가 다르면 지금 레이트를 이어 가고, macOS 가 변환합니다.

레이트를 곡에 맞추는 일은 사용자가 곡을 직접 골라 시작할 때, 소리가 나기 전에만 합니다. 곡마다 알아낸 레이트는 서비스와 근거(곡 · 앨범)를
가려 기억해 두었다가 그때 씁니다. 같은 앨범이라도 발매판이 다르면 같은 기억으로 보지 않습니다.

## Trellis 는 왜 재생을 멈추기도 하나요?

Trellis 는 앞으로 올 소리까지 내다보며 비트를 고르는 변환 방식이라 계산이 무겁습니다. 소리는 정해진 시각마다 DAC 에 닿아야 하는데
이 Mac 이 그 시각까지 계산을 끝내지 못하면, 끊긴 소리를 내보내는 대신 재생을 멈추고 이유를 알립니다. 이때 ‘정밀’ · ‘안전’ 이나 CLANS 로 바꾸면
계산이 가벼워집니다. Fidenne 은 방식을 저절로 바꾸지 않고, 고르는 것은 사용자의 몫입니다.

## Cardinal Sinc 128K · 64K 는 다른 필터와 무엇이 다른가요?

장탭 확장의 고정 길이 sinc 필터로, 128K 는 탭이 약 13만 개(지연 약 116 ms), 64K 는 약 6만 5천 개(지연 약 70 ms)입니다. 둘 다 컷오프가 22.05 · 24 kHz 로
고정이고, 이름 끝에 **따라감** 이 붙은 짝은 컷오프가 곡의 레이트를 따라갑니다. 44.1 · 48 kHz 곡에서는 짝과 같은 계수라 소리가 같고, 다른 레이트의 곡에서만 다릅니다.
길수록 소리가 나오기까지 걸리는 시간이 늘어 영상과 어긋날 수 있습니다.

## 가사 번역은 어디서 이루어지나요?

번역을 켜 두면 Fidenne 은 위에서부터 차례로 시도하고, 앞 단계가 안 되면 다음으로 내려갑니다 — ① 내 API 키로 고른 AI 제공자(켜 두었을 때만) →
② 이 Mac 안의 Apple 모델(Apple Intelligence, 키 없음, 가사가 Mac 밖으로 나가지 않음) → ③ macOS 번역 → ④ 원문.
①만 가사 원문 줄과 제목 · 아티스트를 고른 제공자에게 직접 보내고 요금이 내 계정에 붙습니다. ②~④는 Mac 밖으로 보내지 않습니다.
Fidenne 은 한 제공자가 실패했다고 다른 제공자로 몰래 바꾸지 않습니다. 무엇이 나가는지는 [개인정보 처리방침](../../PRIVACY.md)에 있습니다.
번역은 이 Mac 에서 보는 개인 감상용이며, 가사와 번역을 다른 곳에 공개할 때의 책임은 사용자에게 있습니다. 가사의 저작권은 각 권리자에게 있습니다.

## Fidenne Inlet 은 왜 따로 설치하나요?

Fidenne Inlet 은 음악 앱이 "스피커"처럼 소리를 보낼 수 있는 가상 오디오 장치입니다. macOS 에서 이런 장치는 앱이 아니라
시스템 오디오 서비스가 불러오기 때문에, 앱 안에 둘 수 없고 시스템 폴더(`/Library/Audio/Plug-Ins/HAL`)에 있어야 합니다.
그래서 설치할 때 관리자 암호를 한 번 묻고, 오디오 서비스를 다시 시작하면서 잠깐 모든 소리가 끊깁니다. 다른 가상 오디오 장치도 같은 방식으로 설치합니다.

설치하는 것은 Inlet 하나뿐이고, 설치 직전에 Fidenne 의 서명이 맞는지 다시 확인합니다. 지우려면 **입출력 · 진단 › 입력과 출력 장치** 에서 **제거…** 를 누릅니다.

설치하고 싶지 않으면 처음 설정에서 **시스템 탭** 을 고릅니다. 설치 없이 되지만 macOS 가 소리를 48 kHz 로 바꿔서 넘겨줍니다.
Inlet 은 재생 앱의 원래 샘플레이트를 그대로 받기 때문에 권장합니다.

## 업데이트는 어디에 접속하나요?

업데이트 확인은 github.com 의 새 버전 안내 파일을 읽습니다. GitHub 은 이 파일이나 새 버전을 `release-assets.githubusercontent.com` 으로
넘겨 줄 때가 있습니다. 앱이 하는 다른 접속은 서버가 다른 주소로 안내해도 허용된 곳일 때만 따라갑니다. 업데이트는 앱이 첫 주소만 확인하고
그 뒤의 안내는 업데이트 도구(Sparkle)가 직접 따라가므로, 이 한 곳만은 앱이 안내를 다시 확인하지 못합니다. 받은 새 버전은 서명이 맞을 때만 설치하고, 설치는 업데이트 창에서 직접 고를 때만 합니다.
무엇이 나가는지는 [개인정보 처리방침](../../PRIVACY.md)에 있습니다.

## Safari 확장은 왜 응용 프로그램 폴더에서 열어야 하나요?

Safari 확장은 Fidenne 앱 안에 들어 있어서, Safari 는 앱이 응용 프로그램 폴더 같은 제자리에 있을 때 그 확장을 찾습니다. 내려받은 .dmg 안에서 바로 열었거나
다운로드 폴더에서 연 앱은 macOS 가 따로 떼어 둔 임시 사본으로 돌려서 Safari 가 확장을 보여 주지 못합니다.
Fidenne 은 이 경우를 알아보고 `Safari 확장은 Fidenne을 응용 프로그램 폴더로 옮긴 뒤 다시 열어야 Safari에 보입니다.` 라고 알립니다.
